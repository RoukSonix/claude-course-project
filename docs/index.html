Суть loop-інженерії

Не «один великий промпт», а цикл із критерієм

Ми ніколи не просили агента зробити все за раз. Ми ставили маленьку ціль з ознакою готовності, агент робив крок, ми перевіряли, виправляли — і повторювали, поки критерій не виконано. Це і є loop-інженерія: будувати роботу так, щоб кожен прохід можна було перевірити.

  • 1Ідеяодин сценарій, чіткий вхід і вихід — нічого зайвого
  • 2Планскіл plan-project → PLAN.md: стек, віхи, критерії готовності
  • 3Декомпозиція3–5 задач (issues) у репозиторії; скіл feature-dev описує фічу
  • 4Збіркакрок за кроком у Claude Code; свої скіли через skill-creator; паралельно — worktrees
  • 5Тестперевірка кожної зміни: тести, code-review, тест браузером через інтеграцію з Chrome у Claude Code
  • 6Деплойгілка → PR → merge → Vercel → наступна фіча

Внутрішній луп — найтугіший: Збірка ⇄ Тест ⇄ Виправлення. Саме він економить час: фіксуємо конкретну ваду точковим промптом, а не переписуємо все з нуля.

Скіли = багаторазові кроки лупа

Що ми клали на кожну станцію

Скіл — це збережений фаховий промпт із власними файлами. Замість переписувати інструкцію щоразу, ви викликаєте /назву — і агент робить велику роботу однаково добре.

Зберіть у закладки

Чек-ліст: з чого починати наступний проєкт

Той самий луп, але як список дій. Пройдіть зверху вниз — і у вас є робоча розробка, а не «купа коду».

  1. Ідея
    Один основний сценарій. Чіткий вхід, чіткий вихід. Усе більше — ріжемо.
  2. План
    Скіл plan-project → PLAN.md: простий стек, 3–5 віх, критерії «готово».
  3. Декомпозиція на задачі
    Розбити на 3–5 issues у репозиторії. Скіл feature-dev описує кожну фічу.
  4. Збірка зі скілами
    Крок за кроком у Claude Code. Перевикористовуйте скіли; складне — паралельно у worktrees.
  5. Тестування
    Перевіряйте кожну зміну: тести, code-review, тест браузером через інтеграцію з Chrome у Claude Code. Виправляйте точково, не переписуйте все.
  6. Деплой
    Гілка → PR → merge → Vercel. Секрети лише в env. Далі — наступна фіча.
